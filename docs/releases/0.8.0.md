# Upgrading to Kranz 0.8.0

## The configuration path is an option

Up to 0.7, Kranz accepted a configuration file as its first positional
argument. From 0.8.0 the first positional argument is always a subcommand, and
a configuration path is passed with `-f`:

```bash
kranz prod.yaml     # 0.7
kranz -f prod.yaml  # 0.8.0
```

Kranz recognises the old shape and says what to do instead:

```console
$ kranz prod.yaml
Kranz: unknown command "prod.yaml".
Did you mean `kranz -f prod.yaml`?
```

Bare `kranz` opens the TUI as before, and every 0.7 configuration file loads
unchanged.
