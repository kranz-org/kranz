# Kranz 0.16.1

Kranz 0.16.1 fixes log navigation, configuration reload, and runtime selection.
It has no configuration migration.

## Review configuration changes before applying them

The TUI watches the selected configuration sources and marks changed content.
It keeps the current runtime configuration until you press `Ctrl+L`. This also
applies when a change is found while another configuration check is running.
The CLI `kranz reload` and MCP `reload` remain explicit ways to apply changes.

If a reload removes a running service, the TUI asks whether to stop it first,
keep it running while removing it from the configured service list, or cancel.
If the service cannot stop, the reload leaves the accepted configuration in
place and reports why. Running services renamed by a reload retain their run
history and do not take over an occupied target name.

## Navigate retained output reliably

The log panels and action output keep the selected row in view while output
grows. This includes wrapped lines, filtered results, pinned output, and long
run histories. Clearing output or deleting a retained run updates the visible
window and cursor immediately. Managed service restarts keep the default
retained log history.

Captured output is assembled into complete lines even when a process writes a
line in several pieces. An incomplete line uses bounded memory, and a
readiness marker from a previous run cannot mark a new run ready.

## See every choice in the TUI

The action parameter form puts radio and checkbox options on aligned lines
when they do not fit beside the field name. Long individual labels wrap too.
The log header uses the same dot separator around `WRAP` and `TIME` as it does
before the run selection.

## Select the intended runtime

CLI, MCP, and TUI calls preserve the selected project and configuration source.
A same-named runtime in another directory is not substituted. Configuration
watching also respects selected globs, discovery depth, and symlink policy.

For complete behavior, see [TUI](../guide/tui),
[configuration](../guide/configuration), and
[logs and runs](../guide/logs-and-ports).
